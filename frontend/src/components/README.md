# Pixel Studio component APIs

Studio components are Lit custom elements. Import a component module once (the studio entry point already imports them), then set object-valued properties with Lit property bindings such as `.hass=${hass}`. All visual chrome uses `TOKENS_CSS`; LED plate and pixel colours are content.

## Shell and routing

- `<iledclock-studio-panel>` accepts `.hass`, `narrow`, and optional `device-id`. It resolves the selected clock and renders the app shell, five destinations, and settings sheet.
- `<iledclock-app-shell>` accepts `.hass`, `.entryId`, `.deviceId`, `.route`, and `narrow`. It reads/writes `/iledclock/{now|create|explore|library|alarms}` and sheet query values (`item`, `design`, `alarm`), listens to browser Back/Forward, and passes state events through. The bottom bar on phones holds all five destinations.
- `<lu-nav>` accepts `.options` (`{value,label,icon}[]`), `value`, and `label`; emits `destination-selected` with `{value}`.
- Destination elements accept `.hass`, `.entryId`, `.route`, and `narrow`. Explore consumes `.route` for item-sheet deep links; Create consumes `.route.design`.

Shell events: `route-changed` (`{route}`), `device-selected` (`{deviceId}`), `settings-requested` (optional `{section}`; without one, settings opens at Display; quick rows may request `night-mode`), `clock-status` (state envelope), and `hass-toggle-menu`. The shell handles bubbled `iledclock-open-design` (`{design_id}`) and `lu-toast` events. A toast request has `{message, actionLabel?, action?, timeoutMs?}`; Undo actions should restore the previous shown item rather than repeat an upload.

`lib/route.ts` exports `parseStudioRoute`, `serializeStudioRoute`, and `navigateStudioRoute`. Routes are represented by `StudioRoute`: `{destination, item?, design?, alarm?}` (`alarm` is `new` or an item key and opens the Alarms edit sheet).

## LED and artwork

- `<iledclock-led-preview>` accepts `.frames` (`PixelFrame[]`), `.delays` (`number[]`), `context` (`hero`, `editor`, `tile`, `thumb`), optional `max-pitch`, `zoom`, `playing`, `rate` (default 1) and `label`. `rate` multiplies playback speed (elapsed time x rate); changing it keeps the current position in the loop, whereas new `.frames`/`.delays` restart at frame 0. It owns integer-pitch sizing, caps animation updates at 60 fps, and stops when hidden or reduced motion is enabled.
- `<iledclock-art-tile>` accepts `item-id`, `image-url`, optional `media-path` (the unsigned HA media path), `.frames`/`.delays`, `animated`, `aspect` (`square` or `design`), `title`, and `subtitle`. Animated artwork shows a still poster until focused or hovered with a fine pointer; touch devices never autoplay. With `media-path`, retries emit bubbling/composed `media-retry-request` with `{itemId, mediaPath}`. Tile playback shares a 12-item animation budget.
- `lib/led-size.ts` exports `ledSizeFor(context, availableWidth, availableHeight, options?)`. Returned `pitch`, `width`, and `height` are whole-pixel dimensions. `lib/tile-policy.ts` exports retry and active-animation-budget policies for tests and consumers.

The existing `<iledclock-hold-button>` accepts `label`, `complete-label`, `danger`, `disabled`, and a `.config` object (`{durationMs, drainMs}`; the default hold lasts 1500 ms). It emits `confirmed` only after a complete press-and-hold; keyboard Space/Enter follows the same hold/release lifecycle. The segmented picker and stepper remain shared editor controls and inherit the Lucent token layer.

## Speed and Smooth motion

`<iledclock-playback-control>` is the reusable Speed slider plus the Smooth motion switch for one `PlaybackSession` (`lib/playback-session.ts`). Properties: `.session` (required), `label` (default "Speed"), `disabled`. It renders nothing for a single picture (`session.hasMotion === false`). Events (bubbling, composed, `detail: {speed, smooth}`): `playback-input` on every drag step and every keyboard/switch change, `playback-commit` when the user settles (release, keyboard, switch, Reset). The control never talks to the server itself.

`PlaybackSession` is framework-free. Construct with `{callWS, buildRequest, onChange?, defaultState?, debounceMs?, setTimer?, clearTimer?}`. `buildRequest(state, authoredFrames)` returns the `iledclock/playback/preview` message (`playbackPreviewRequest` from `lib/ws-api.ts`). Methods: `setSource(frames, {state?})` (new authored frames; fetches at once; `state` sets the starting and the Reset state; the same array again is a no-op), `setState({speed?, smooth?}, {commit?})` (no `commit` = drag step: local rescale only; `commit: true` = exact request after a 200 ms debounce), `reset()`, `setDefaultState(state)`, `refresh()`, `subscribe(listener)`, `dispose()`. Reads: `state`, `speed`, `smooth`, `frames` (`PixelFrame[]`), `delays`, `rate`, `playing`, `loading`, `error` (plain text, hosts show it), `info` (`PlaybackInfo | null`), `hasMotion`, `authoredFrames`, `nativeFps`, `originalSpeed`, `loadedPace`. Reset restores `defaultState`, so a host showing a stored design passes that design's speed/smooth as the `setSource` state. Speed is `null` (Original), `0` (Still) or 1..100; `smooth` is `"on" | "off" | null`. The pure maths and copy (`paceForSpeed`, `snapSpeed`, `steppedSpeed`, `describeSmooth`, `designLoopCaption`, ...) are in `lib/playback.ts`.

Host wiring:

```ts
const session = new PlaybackSession({
  callWS: (request) => hass.callWS(request),
  buildRequest: (state) => playbackPreviewRequest({ designId: design.id, entryId }, state),
  onChange: () => this.requestUpdate(),
});
session.setSource(designToFrames(design), { state: { speed: design.speed ?? null, smooth: design.smooth ?? null } });
// render():
html`<iledclock-led-preview .frames=${session.frames} .delays=${session.delays} .rate=${session.rate} ?playing=${session.playing}></iledclock-led-preview>
  <iledclock-playback-control .session=${session} @playback-commit=${this._saveSpeed}></iledclock-playback-control>`;
// The control shows session.error itself (role="alert"); the host never renders it.
// _saveSpeed(e): hass.callWS(designsSetPlaybackRequest(design.id, e.detail)); disconnectedCallback(): session.dispose();
```

## Screens A and B

The clock has two screens behind its power button. Bluetooth cannot pick one and nothing can be read back, so a screen changes only when something is sent to it: every show goes to screen A (the program list) unless the request carries `slot: "b"` (screen B, the clock-page store: clock, date, temperature and humidity pages, and designs with a clock while the server's `capabilities.slots.b_accepts` says so). `lib/slots.ts` holds every rule (pure, unit-tested): `getSlotChoice` / `setSlotChoice` (the remembered screen, per clock, in `localStorage`, in memory when storage is blocked; `slotChoices.subscribe` is the change event), `slotAllowance(slot, contentClass, capabilities)` (`{ok, reason}`, reasons copied from `slots.py`), `effectiveSlot(entryId, contentClass, capabilities)` (the remembered B only when this content may go there, else A), `contentClassOf(showItem | descriptor | design, designs?)`, and `resolveSlot` / `loadSlotCapabilities` / `primeSlotCapabilities` (capabilities fetched once per clock for surfaces that do not hold the live state; with B remembered and the list unreadable, nothing is sent).

- `<iledclock-slot-choice>` is the compact "Screen A | B" control placed beside every Show action (mode deck clock/text/art, Explore item sheet, Import sheet, Library design sheet footer, editor header). Properties: `.hass`, `.entryId`, `content-class` (a `ContentClass`, default `art`), optional `.capabilities` (the live state's; otherwise looked up once and cached), `label`, `disabled`; emits `slot-selected` (`{slot}`). It shows where a Show goes right now: when B cannot take this content it shows A, greys B (`aria-disabled`, still focusable) and gives the server's reason in one line linked by `aria-describedby`. The remembered choice only changes when an available segment is tapped, so B returns for the next clock face. A date page is the exception: the clock always files it on screen B (a rule of the wire format, not a capability), so for `content-class="date"` the control shows B selected and A greyed with "The clock always keeps its date page on screen B.", and the remembered choice is left alone. While B is remembered and the clock's reply about what B takes is still out, neither segment is selected (a Show waits for the same reply). Arrow keys, Home and End move the choice (`keyedSlot` in `lib/slots.ts`; Alt, Ctrl and Meta combinations are left to the browser) and the handled keys do not bubble, so they never also trigger a parent such as the Explore sheet's previous / next artwork. Switching clock while the first capability request is out starts the new clock's own request and ignores the old answer.
- `<iledclock-slot-tiles>` (Now below the hero, and in the Lovelace card): `.hass`, `.entryId`, `.slots` (`SlotsState`). Two tiles, "Screen A" and "Screen B", each a record of what Home Assistant SENT (picture rendered by the server from the stored descriptor, title, "Sent 5 min ago"), a "Last sent" marker on `slots.last_written`, "Nothing sent from Home Assistant yet" when empty, and the caption "Press the clock's power button to switch". The tiles are a radio group for the TARGET (the same remembered choice as every A | B control). They never claim to know which screen the clock is showing: the power button is invisible to Home Assistant. Arrow keys, Home and End move the target (same `keyedSlot`); only the target tile is a tab stop.
- `showWithUndo(host, hass, entryId, item, title, options?)` takes `options.slot` (an explicit screen) or `options.contentClass` (+ `options.capabilities`), in which case the screen is decided at click time from the remembered choice. The toast names the screen when it is B ("Now showing X on screen B"), and says "on screen A" when B was remembered but this content cannot go there. Undo needs no slot: the server goes back on the screen of the entry being undone. A `slot_unsupported` refusal shows the server's reason and offers no Retry. A surface whose show runs after a wait (an import or a save: the Explore item sheet, the Import sheet, the editor) must not decide the screen afterwards, because the layout and clock-region controls stay live meanwhile. It calls `resolveShowTarget(hass, entryId, contentClass)` at the click (null = B is remembered but what it takes cannot be checked: nothing is sent and the sheet says so), keeps the `{slot, fellBack}` answer together with the artwork options it fixes at that moment, and passes it as `options.target`; the show goes exactly there, and a screen the content then cannot take is refused by the server with its reason, never redirected.
- `lib/descriptor-preview.ts` turns a `now_showing` / history / slot-record descriptor into frames (`descriptorPreviewPlan`, `descriptorPreviewKey`, `loadDescriptorPreview` with a shared 60 s cache, `decodeRenderFrames`). Now, the card and the tiles share it, so the hero and the tile of the screen it was sent to cost one request. The clock draws date, temperature, humidity, timer and scoreboard pages itself, so those get a sentence instead of a picture. Text speeds in descriptors written before screens existed (old 0-255 scale, no `slot`) are ignored.

Text mode of `<iledclock-mode-deck>`: the text is drawn to frames on the server (`iledclock/render {type:"text"}`: `effect` "1" solid / "2" rainbow / "4" per-letter rainbow, `bold`), the preview animates those exact frames, and the Speed control is the shared `<iledclock-playback-control>` (0-100, Original, Smooth motion) fed the frames at Original pace through a `PlaybackSession`; it only shows while the text scrolls (text that fits 32 columns is one still frame). `buildTextRenderSpec(text, colour, {font?, effect?, bold?, speed?, smooth?})` sends `speed` only as a whole number 0-100 (Original = no key).

`<lu-sheet>` now keeps its footer slot out of the scrolling body and hides it when empty; a soft fade at the bottom of the body (and a hairline under the header once scrolled) says there is more to scroll to. The Library design sheet keeps its actions (screen choice, Show on clock, Edit, Duplicate, Add to rotation, hold to delete) in that footer.

## Alarms & reminders

- `<iledclock-dest-alarms>` (`.hass`, `.entryId`, `.route`, `narrow`) reads `iledclock/state` and subscribes like Now, loads `iledclock/designs/list`, and shows the list from `reminder_list`: slot chip, rows sorted by next ring, status lines with Re-send, the "On the clock only" section, and the empty, loading, error, full and out-of-range states. It drives `reminder_set_enabled`, `reminder_resend` and `reminder_delete`, owns the sheet's route (`?alarm=`), and toasts through the shell's `lu-toast` event. Clock-dependent actions are disabled while the clock is out of range.
- `<iledclock-alarm-sheet>` (`.hass`, `.entryId`, `open`, `.item` (a `ManagedReminder` or null for a new one), `.list`, `.capabilities`, `.designs` (null until loaded), `.textArt`, `.upload`, `connected`) is the edit form. It validates with `lib/reminders.ts`, saves with `reminder_set`, deletes with `reminder_delete`, and emits (bubbling, composed) `alarm-saved` `{item, created}`, `alarm-deleted` `{key, name}` and `close-requested`. The art picker opens as a second pane inside the same `lu-sheet`.
- `<iledclock-alarm-art-picker>` (`.hass`, `.entryId`, `.designs`, `.value` (a `ReminderAttachment`), `name`, `max-frames`, `.textArt`, `disabled`) is a radio group of "Name as text" plus the Library designs with a large live preview; it emits `art-selected` `{attachment}`. Ineligible designs (live-clock area, too many frames) are listed disabled with a one-line reason.
- The picker also emits `art-preview-state` `{pending}` while the exact picture of the chosen design is being drawn (the sheet keeps "Use this art" off meanwhile). `lib/reminders.ts` adds `wallClockNow(timeZone, instant?)` (a Date whose local getters read Home Assistant's wall clock; the components pass it `hass.config.time_zone`), `editingRecord(list, key, opened)` (the stored item a form edits, looked up by key in the current list), and `playedFrameCount` / `designEligibility` (art is judged by the frames played: Still = one frame).
- `lib/reminders.ts` is pure and unit-tested (`tests/frontend/reminders.test.ts`): `slotsNeeded` (mirrors the server's cost table and takes the `week_mask` capability), `repeatSummary`, `nextRing` / `describeNextRing`, `sortReminders`, `formatClockTime` and `timeLocaleFromHass` (Intl with Home Assistant's language and 12/24 h), `statusView` / `savedStatusText`, `slotChip`, `availableSlots`, the form model (`blankForm`, `formFromItem`, `formToInput`, `changeRepeat`), `validateForm` (mirrors the server's checks), `designEligibility`, and `TextArtCache` (draws each name once through `iledclock/render`, two requests at a time). `lib/radio-keys.ts` holds the radio-group arrow-key rules.
